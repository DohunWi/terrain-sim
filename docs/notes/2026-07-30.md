# 2026-07-30 — Phase 2a 시작: RigidBody, semi-implicit Euler, 지형 충돌

### 연산자 오버로딩
- C++은 `operator+`, `operator*` 같은 걸 **멤버 함수**로도, 클래스 밖 **자유 함수**로도 둘 다 쓸 수 있음 — C#은 항상 `static` 멤버로만, Python은 `__add__` 매직 메서드로만 강제되는 것과 다름.
- 멤버 함수로 짜면 `a + b`는 `a.operator+(b)`로 해석됨 — 그래서 `a * 2.0f`는 되지만 `2.0f * a`는 안 됨(왼쪽이 클래스 인스턴스가 아니면 멤버 함수 문법으로는 못 잡음). 양방향을 다 지원하려면 클래스 밖에 자유 함수 오버로드를 따로 추가해야 함.

### 괄호 `()` vs 중괄호 `{}` 초기화
- 멤버 함수/생성자가 없는 struct(aggregate)에 대해 `Vec3{0,0,0}`은 원래부터(C의 `struct init = {...}`와 사실상 같은) 됐지만, `Vec3(0,0,0)`은 **C++17까지 컴파일 에러**였음. C++20에서 새로 허용된 문법(P0960).
- `{}`는 narrowing 변환(예: `double` → `int`)을 컴파일 에러로 막아주는데 `()`는 조용히 통과시킴 — `int a{3.14};`는 에러, `int a(3.14);`는 그냥 3으로 잘려서 컴파일됨.
- `std::vector<int> v(5, 1)`과 `std::vector<int> v{5, 1}`은 완전히 다른 결과 — 전자는 "5개, 값 1"(원소 5개), 후자는 initializer_list 생성자가 우선 선택돼서 원소 2개(`5`, `1`). 똑같이 생긴 코드가 다른 뜻이 되는 대표적인 함정.

### Semi-implicit (symplectic) Euler 적분
- 자유낙하를 `velocity += gravity*dt` 먼저, 그다음 `position += velocity*dt`(갱신된 속도로) 순서로 적분 — 이 순서 자체가 "semi-implicit"이라는 이름의 이유. 순서를 반대로 하면(옛날 속도로 위치를 먼저 갱신) explicit Euler가 되는데, 그건 시간이 지날수록 에너지가 계속 새어 늘어나는 방향으로 불안정해짐.
- 계산 비용은 explicit Euler와 완전히 같은데 훨씬 안정적이라 실시간 게임엔진/시뮬레이터가 기본으로 씀 — Unity `Rigidbody`가 `FixedUpdate`마다 내부적으로 하는 게 이거였다는 걸 이번에 처음 직접 구현하며 이해함.
- 검증 방법: `n`스텝 후 위치의 닫힌 형태 공식(`y_n = -g·dt²·n(n+1)/2`)과 시뮬레이션 출력값을 비교 — 소수점 4자리까지 일치. "돌아간다"가 아니라 "맞다"를 확인하는 방법을 직접 손으로 검산해본 첫 사례.

### 지형 충돌 + 힘 기반 제어
- `Heightmap::sample()`로 임의의 `(x, z)` 위치의 지형 높이를 쿼리해서, `position.y < groundHeight`면 clamp — 상수 바닥이 아니라 펄린 노이즈로 만든 진짜 굴곡진 지형 위에서도 정확히 그 지점의 높이에 멈추는 걸 확인.
- 힘을 가속도로 바꿀 때(`F/m`) `Vec3`에 나눗셈 연산자가 없어서 `force / mass` 대신 `force * (1.0f/mass)`로 우회 — 필요 이상으로 연산자를 늘리지 않는 선택.
- **버그 하나 발견 및 수정**: `Heightmap::sample()`이 이웃 격자점(`x0+1`, `y0+1`)을 읽을 때 범위 체크가 전혀 없었음 — droplet erosion은 우연히 항상 안전한 범위에서만 호출해서 안 드러났는데, 물리 바디가 옆으로 움직이기 시작하면 지형 밖 좌표로 배열 밖 읽기(UB)가 날 수 있는 상황. `std::clamp`로 격자 인덱스를 유효 범위에 고정해서 해결 — "어떻게 호출되든 클래스 자신의 불변조건은 클래스가 지켜야 한다"는 설계 원칙을 실제 버그로 겪어봄.
- Sanitizer(`-fsanitize=address,undefined`)로 검증하려다 샌드박스 환경 제약으로 실행이 멈추는 걸 겪음 — macOS에서 ASan이 필요로 하는 프로세스 조사 권한을 샌드박스가 막아서 생기는 환경 문제였고, sanitizer 없는 일반 빌드로 극단적인 범위 밖 입력을 직접 넣어보는 걸로 대신 검증함. 도구가 안 먹힐 때 다른 경험적 검증 방법으로 우회하는 것도 실전에서 자주 필요한 능력.
