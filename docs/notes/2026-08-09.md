# 2026-08-09 — 반발계수·마찰 물리, 회전 운동 warmup

프로젝트 산출물 작업은 Phase 2d-2에서 마무리했고, 이제부터는 `practice/`에서 개인 학습으로 다루는 주제들이다. 첫 주제는 강체 접촉 물리(반발계수·마찰)이고, 이어서 회전 강체 동역학을 시작했다.

### 반발계수(coefficient of restitution)와 임펄스

- `v_normal_after = -e·v_normal_before` (0≤e≤1) — 접촉 순간 법선 방향 속도만 이 공식으로 바꾸고 접선 방향은 그대로 두면 충돌 응답이 만들어진다. `e=0`이면 완전 비탄성(속도가 그냥 사라짐), `e=1`이면 완전 탄성(그대로 반사).
- 처음엔 접선/법선을 따로 변수로 분리해서 계산했는데, 대수적으로 정리하면 `velocity_after = velocity - (1+e)·v_normal`로 한 줄에 끝난다는 걸 확인했다 — `v_tangential`을 명시적으로 만들 필요가 없다(단, 마찰을 추가하는 순간 다시 필요해진다. 마찰은 접선 성분에만 작용하니까).
- **이산 시간 시뮬레이션에서 반발계수의 함정**: 이론적으로는 `e<1`이면 bounce가 유한 시간 안에 무한히 여러 번 일어나며 수렴해서 표면에 완전히 붙어야 한다(기하급수). 그런데 고정 `dt`로 이산화하면 이게 안 된다 — bounce 에너지가 아무리 작아져도 "충돌 직후 표면 밖으로 향하는 속도"가 항상 0보다 크게 나오는 한, 다음 프레임엔 무조건 다시 "공중" 판정을 받는다. 실측해보니 apex height가 계속 줄다가 `~0.0009`라는 고정된 바닥값에서 멈추고 더 이상 안 줄어들었다 — 이론과 시뮬레이션이 갈라지는 지점을 직접 측정으로 잡아낸 사례.

### impulsive 마찰 vs continuous 마찰은 다른 물리다

- Coulomb 마찰(`|마찰력| ≤ μ·|수직항력|`)을 충돌 임펄스 관점에서 쓰면 `J_t_max = μ·J_n`(여기서 `J_n`은 반발계수 적용으로 생긴 법선 방향 속도 변화량의 크기)이고, 접선 속도를 `min(J_t_max, speed_t)`만큼만 깎으면 된다 — 역전(방향이 뒤집히는 것)은 항상 막아야 한다.
- 근데 이건 **충돌 순간에만** 성립하는 모델이다. 물체가 경사면에 계속 붙어서 미끄러지는 상황(진짜 접촉, 순간 충돌 아님)에서는 수직항력이 임펄스가 아니라 **중력의 법선 성분**(`N = |gravity_normal|`)에서 나오고, 마찰력도 매 프레임 `μ·N·dt`만큼 계속 깎아야 한다. 처음에 이 둘을 구분 못 하고 한 코드 경로에 같이 넣었더니, "충돌해서 튕겨나가는 프레임"과 "계속 미끄러지는 프레임"이 구분 안 되는 문제가 생겼다.
- 두 모델을 하나로 합치려면 **분류 기준**이 필요하다: 접촉 진입 시점의 법선 속도 크기(`|v_n_before|`)가 어떤 임계값(`epsilon`)보다 크면 진짜 충돌(impulsive), 작으면 이미 안착한 상태(continuous)로 분기한다.

### 물리 코드를 합치다가 만난 버그 네 종류 (전부 빌드+실행으로 잡음, 눈으로 안 보임)

1. **부호 버그**: 마찰을 뺀다는 게 `normalize(velocity)*g_removed`를 **더해서** 오히려 가속시키고 있었다. 접선 속도가 bounce를 거듭할수록 계속 커지는 로그를 보고서야 눈치챘다.
2. **스코프 버그**: 마찰 크기를 클램프할 때 `length(velocity)`를 썼는데, 이 시점의 `velocity`엔 법선 방향(튕겨나가는) 성분까지 섞여 있었다. 접선 성분만 따로 참조해야 했다.
3. **순서 버그**: `velocity = velocity + g_tangential*dt`를 계산해놓고, 그 다음 줄에서 `velocity = v_tangential_after + v_normal_after`로 통째로 덮어써버려서 중력 가속 항이 조용히 사라졌다. 이건 로그만 봐서는 안 잡혀서, 스크래치 디렉토리에 파일을 복사해 최종 접선 속도를 직접 찍는 임시 계측을 추가하고서야 확인했다 — `기대값(잔여속도+중력항-마찰) == 실측값`을 직접 비교.
4. **`wasAirborne` 갱신 위치 버그**: 원래 `if/else` 전체 바깥에서 매 프레임 무조건 갱신돼야 하는 플래그가, 리팩토링 과정에서 한쪽 서브 분기 안으로 들어가버렸다. 물리 계산 자체는 안 틀렸는데 "새 bounce인지" 판단이 깨져서, 계측(리포트 함수 호출)이 첫 bounce 이후로 전부 안 찍혔다 — **물리가 맞아도 계측 코드의 버그 때문에 검증이 무의미해질 수 있다**는 걸 직접 겪음.

이 중 1~3번은 전부 "값이 이상하게 커진다/작아진다"는 관찰에서 출발했고, 코드를 눈으로 다시 읽는 것보다 실제 수치를 찍어서 기대값과 비교하는 게 훨씬 빨랐다.

### `epsilon` 임계값도 숫자를 잘못 고르면 의도가 실현 안 된다

- 처음 `epsilon`을 "중력이 한 프레임 동안 법선 방향으로 넣어주는 속도"(`length(g_normal)*dt`)로 물리적으로 그럴듯하게 골랐는데, 실제로 3000프레임(944 bounce)까지 돌려봐도 continuous 분기에 한 번도 안 들어갔다. 이유는 반발계수 bounce 자체가 수렴하는 수치적 바닥값(`~0.209`)이 이 `epsilon`(`~0.156`)보다 커서, 아무리 오래 돌려도 그 바닥 위에서 영원히 맴돌기 때문이었다.
- `epsilon`을 초기 bounce 크기들과 수치적 바닥값 사이의 값(`0.25`)으로 다시 고르니 실제로 7번 진짜 충돌하고 그 다음부터 깨끗하게 continuous 미끄러짐으로 전환됐다. **임계값은 "물리적으로 의미 있어 보이는 공식"만으로는 부족하고, 실제 시뮬레이션이 만들어내는 수치 분포와 비교해서 검증해야 한다**는 걸 배웠다.
- 여담: 이 검증 과정에서 급하게 짠 awk 극값 탐지 스크립트를 과신해서 "4번 튕기고 정착한다"는 잘못된 결론을 먼저 냈다가, 더 긴 구간을 다시 돌려서 스스로 정정했다. 빠른 확인 스크립트도 결국 검증이 필요한 코드라는 걸 다시 확인.

### 회전 운동 warmup: 병진-회전 대응

- `F=ma` ↔ `τ=Iα`, `v` ↔ `ω`, `x` ↔ `θ`, `½mv²` ↔ `½Iω²` — 이 대응을 그대로 따라가면 2D 회전(고정축)은 병진운동 코드와 구조가 완전히 같다.
- 물리 진자(`τ = -mg(L/2)sinθ`, `I=(1/3)mL²` — 막대 한쪽 끝 기준)를 semi-implicit Euler로 적분하고 에너지(`½Iω² + mg(L/2)(1-cosθ)`)를 측정했다. 90프레임(1.5초) 동안 최대 편차 2% 이내로 유계 — Phase 2d-2에서 확인했던 semi-implicit Euler의 symplectic 특성(에너지가 발산하지 않고 초기값 주변에서 진동)이 그때는 1D 조화진동자(선형)로 검증했는데, 이번엔 실제 `sinθ` 비선형계에서도 같은 성질이 유지된다는 걸 다시 확인한 셈.
- 다음 단계: 3D에서는 관성모멘트가 스칼라가 아니라 3x3 텐서여야 하는 이유(질량 분포가 비대칭이면 각속도 `ω`와 각운동량 `L`이 다른 방향을 가리킴) — 개념은 정리했고, 대각행렬로 표현되는 직육면체 관성텐서로 `L`과 `ω`의 방향이 갈라지는 걸 직접 계산해보는 것부터 다음 세션에서 시작한다.
