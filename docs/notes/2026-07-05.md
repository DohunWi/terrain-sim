# 2026-07-05 — Phase 0: C++ 기초 + 열 침식 워밍업

### 빌드 시스템
- C++은 파일 단위로 각각 컴파일된 후(`.o`) 링커가 하나로 합침(Python/C#의 "한 번에 다 컴파일"과 다름). 헤더(`.h`)는 이 분리된 컴파일 단위끼리 서로의 존재를 알려주는 설계도 역할.
- CMake는 컴파일러가 아니라 "실제 컴파일 명령어들을 생성해주는 도구". `cmake -S . -B build`(구성) → `cmake --build build`(빌드) 2단계. `CMakeLists.txt`가 바뀌면 `--build`만 다시 돌려도 자동으로 재구성됨.

### 포인터 / 참조 / 스마트 포인터
- 포인터(`T*`): null 가능, 재할당 가능. 참조(`T&`): 한 번 묶이면 재할당 불가, null 불가 — C#의 `ref` 파라미터와 동일한 개념.
- `unique_ptr`는 복사 생성자가 명시적으로 삭제되어 있어서 복사가 아예 컴파일 에러남 — **런타임 double-free 버그를 컴파일 타임 에러로 옮기는 설계**. `std::move`로 소유권 이전은 가능(이동 후 원본은 비워짐, nullptr 상태).
- RAII는 `unique_ptr`만의 기능이 아니라 일반적인 패턴 — `vector`, `string`, `ifstream`, `lock_guard` 등 다 해당. 멤버가 전부 RAII 타입이면 클래스 자체도 소멸자 없이 자동으로 RAII가 됨.

### 열 침식(Thermal Erosion) 구현
- 알고리즘: 각 셀에서 가장 낮은 이웃(4방향)을 찾고, 그 차이가 임계각(talus angle)을 넘으면 초과분을 이동. 매 iteration마다 읽기용/쓰기용 heightmap을 분리(더블 버퍼링)해서 순서 의존성 버그 방지.
- 검증: 침식 전/후 전체 높이 합이 정확히 일치 → 질량 보존 확인됨 (spec 요구사항).
- **알려진 한계**: 가장 낮은 이웃 "하나"에게만 몰아주는 단순화된 방식이라, 동점 상황에서 `dx/dy` 배열 순회 순서 때문에 특정 방향(아래/오른쪽)으로 쏠리는 현상 발견. 질량 보존은 깨지지 않지만 등방성(isotropic)은 아님. 다중 이웃 비례 분배로 개선 가능하나 Phase 0 범위에서는 보류.
- PGM(P2, 텍스트 그레이스케일) 포맷으로 결과 출력 — heightmap의 min/max로 정규화해서 0~255 정수 변환.

### 흔히 헷갈렸던 문법
- `#pragma once`: `#include`가 텍스트 복사-붙여넣기 방식이라 같은 헤더가 중복 포함될 때 재정의 에러를 막는 지시자.
- `Heightmap::Heightmap(...)`의 `::`: 헤더에서 선언만 한 멤버 함수를 `.cpp`에서 구현할 때 "이 클래스 소속"임을 명시하는 연산자.
- 초기화 리스트(`: width_(width), ...`): 생성자 본문 실행 전에 멤버를 바로 그 값으로 생성 — `vector`처럼 생성 비용이 있는 멤버에 유리.
- `std::`는 클래스가 아니라 네임스페이스. 그 안에 클래스(`vector`), 객체(`cout`), 함수(`move`)가 섞여 있음.
- for문 `(초기화; 조건; 증감)` 순서를 헷갈려서 `for(int y=0; y++; y<h.height())`처럼 조건/증감 위치를 바꿔 쓴 실수 발견 — 컴파일 에러 없이 조용히 루프가 0번 실행되는 버그였음. 경고로도 안 잡히는 논리 버그의 실제 사례.
